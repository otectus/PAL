# PAL 2.0.2 provider validation

The provider work was integrated into a checkout that also contained ongoing Research and client work. The handoff used PAL bd8f2e2 and Py-GPT a6766d0 as its reference. The local PAL base advanced to 596ebe2 during implementation.

The results below were recorded on November 23, 2026 for the provider work. The checks of the complete release are in [VALIDATION.md](../../VALIDATION.md).

## Architecture and migration evidence

The broker registry owns provider IDs, import aliases, dialects, service operations, schema-driven options and default processing routes. A saved account has its own ID, endpoint, revision, optional deployment, credential reference and model catalog. The managed conversation runner supplies project context, personality, memory and PAL tools. Native dialects retain provider-specific reasoning, tool results and signatures where their original account and model can use them. Portable continuations preserve readable history when an account or model changes.

The mobile protocol remains at major version 1. New operations advertise feature flags. Signed owner requests use the desktop’s secrets, and restricted clients are checked against the project, operation and account grant at dispatch. Realtime audio uses bounded, sequenced encrypted binary frames. File originals, inference outputs, OCR text and generated media refer to immutable Workbench versions. Jobs persist their provider handles across broker and client restarts.

The migration fixture opened a pre-upgrade SQLite profile, checked the backup's contents and 0600 mode, reran the migration, and verified the backup was unchanged. Its Py-GPT import fixture mapped the xAI and HF Router IDs, reported duplicate accounts and unknown fields, rejected a stale preview, and confirmed that ordinary imports exclude keys and executable fields. Optional credential import has separate tests for endpoint binding, explicit confirmation and rollback. Retired Sonar names persist as reviewable migration records. The current Agent catalog offers Quick answer and Research presets and supports manually entered live model IDs. [Credential import tests](../../tests/provider-import-secrets.test.ts) [Migration and account tests](../../tests/provider-services.test.ts)

## Reproducing the release checks

From the repository root:

```sh
npm ci --no-audit --no-fund
npm run typecheck
npx tsc -p tsconfig.mobile.json
node tools/mobile-contract.ts --check
taskset -c 0-3 npm test
npm run build
LIBGL_ALWAYS_SOFTWARE=1 xvfb-run -a ctest --test-dir build --output-on-failure
QT_QPA_PLATFORM=offscreen QT_QUICK_BACKEND=software build/pal-ui-check apiProviderSetup
python3 tools/install-user.py --prefix "$PWD/build/pal-2.0.2/desktop"
build/pal-2.0.2/desktop/bin/pal --version
```

The CPU affinity used for the Node run is specific to the test host. The desktop build requires the Qt and LayerShellQt development dependencies. Generated schemas and the phone operation index come from `node tools/mobile-contract.ts` and `node tools/feature-matrix.ts`.

From `mobile/android` with an Android SDK and an emulator for instrumentation:

```sh
./gradlew :core:protocol:test :core:data:testDebugUnitTest :app:testDebugUnitTest
./gradlew :app:lintDebug :app:lintDev :app:lintRelease :app:assembleDebug :app:assembleDev :app:assembleRelease
./gradlew :app:connectedDebugAndroidTest
```

The local gate logs and APK signature report are in `build/pal-2.0.2/evidence/`. The live observations include upstream limits and the account or deployment needed to repeat each blocked check.
