# PAL Mobile design reference

PAL’s desktop robot has a pearl shell, dark display and cyan eyes. The phone uses these cues for orientation and reserves most screen space for reading. The welcome illustration comes from the existing PAL artwork. After pairing, the conversation header can show the desktop’s chosen character and expression. Android’s font sizes and system light or dark setting apply throughout. PAL keeps its own palette so selection, attention and the companion’s display retain the same meanings across devices. ## Foundation

| Role | Use |
| --- | --- |
| Background and surfaces | Day places light reading surfaces on a pearl background. Night steps from deep ink to raised slate. Use `surfaceContainer` for nested reading aids and exact technical content. Most sections use spacing and a heading. |
| Accent and attention | Use `primary` for the active action, selection, links and progress. Use `tertiaryContainer` with its matching ink for a decision or recoverable interruption. Reserve `errorContainer` and error actions for failures and destructive choices. Always include a label or symbol. |
| Text | Use system sans for language and system monospace for exact paths, code and terminal cells. Reading text is 16 sp with a 25 sp line height. Section titles are 17 or 21 sp. Page headings use 26 or 30 sp. Small metadata uses 13 sp with a 19 sp line height. |
| Layout | Group related elements at 4, 8 or 12 dp. Use 16 dp phone gutters, 24 dp between major sections and a 48 dp minimum interactive target. Cap forms at 560 dp and reading columns at 720 dp. A compact landscape keyboard can reclaim header space. |
| Shapes and boundaries | Shared corners step through 4, 8, 12, 18 and 24 dp. Give the user’s message an asymmetric end corner and let assistant prose occupy the reading column. Use contrasting `outline` or `outlineVariant` on controls. Keep decorative separators quieter. |
| Motion and input | Use Material pressed, focused, disabled and selected states. The connection color settles over 120 ms and request detail expands over 160 ms. These animations use the system duration scale. Status text and selection remain readable with animations disabled. |
| Icons and media | Use Material-style 24 dp symbols and start/end-aware directional icons. An icon-only control needs an action label. Decorative art accompanying equivalent text is silent. Terminal colors, marked-up images, camera contrast and black-and-white QR modules preserve the meaning of the content. |

Implementation lives in [Theme.kt](../../../mobile/android/app/src/main/kotlin/dev/otectus/pal/mobile/Theme.kt). Transfer, terminal and Markdown measurements that depend on content are separate from the spacing scale.

## Components and journeys

- **Conversation.** Keep the primary send or stop control beside the multiline input. Retain queueing when the provider advertises it. Put secondary tools and source lists alongside the message or activity they describe. Stream into stable keyed rows. Follow the last row while reading at the bottom, then leave the reader in place and offer Latest when they scroll away. Code scrolls horizontally and has its own Copy control. The Markdown table scrolls as one grid. [Transcript](../../../mobile/android/app/src/main/kotlin/dev/otectus/pal/mobile/ConversationContent.kt) · [Markdown](../../../mobile/android/app/src/main/kotlin/dev/otectus/pal/mobile/MarkdownContent.kt)
- **Pairing and recovery.** Keep the signed offer, six-word check, Android authentication and desktop confirmation in their existing order. Derive the top bar, conversation status and recovery explanation from the same connection model. When the phone can retry, put the action beside the explanation. Unknown outcomes require reconciliation with the desktop. [Connection presentation](../../../mobile/android/app/src/main/kotlin/dev/otectus/pal/mobile/ConnectionUi.kt)
- **Sensitive requests.** Show the conversation, delegating agent or parent, available project, exact detail, destination URL and image preview where supplied. Put the choices below the request with separate full-width targets. A submitted answer and an unconfirmed answer have different explanations. Approval remains a deliberate choice and the existing signed path performs it. [Request presentation](../../../mobile/android/app/src/main/kotlin/dev/otectus/pal/mobile/MainActivity.kt)
- **Navigation and settings.** Use a bottom bar on a regular phone and a rail in sufficiently wide windows. At large type, use the labelled destination selector. Group settings by purpose with Connection first. Conversation-specific work settings live in its menu, leaving the file, run or research result visible. [Navigation](../../../mobile/android/app/src/main/kotlin/dev/otectus/pal/mobile/Navigation.kt) · [Library and settings](../../../mobile/android/app/src/main/kotlin/dev/otectus/pal/mobile/LibraryUi.kt)
- **Feedback.** Give empty areas a meaningful title and a next step when the phone can act. Show genuine transfer counts where available and indeterminate progress while waiting for the desktop. Preserve desktop-supplied names, command targets and errors as data. Use Android resources for phone-authored messages and plurals.
