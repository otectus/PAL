# Graph memory architecture

Graph memory runs inside the PAL broker. `MemoryService` owns network clients and collectors; a worker thread owns `Canonical` and its single SQLite writer. The UI and CLI use the existing private broker socket. Linux `SO_PEERCRED` enforces same-user connections through the compiled `pal-peercred.node` helper.

SQLite is authoritative. Its strict schema contains source observations, exact Unicode-span witnesses, scoped entities and aliases, identity decisions, fact slots, bitemporal assertion versions, event streams, episodes, topics, artifacts, lineage, commits, projection jobs, response provenance, and erasure records. Versioned schema checksums are verified before serving. WAL, FULL synchronous commits, foreign keys, and secure deletion are enabled. Changing the schema requires a migration; editing an already-applied migration fails closed.

Every canonical mutation obtains a monotonic revision and transaction timestamp. It writes its effects, FTS document changes, and ordered projection jobs in the same transaction. Read tokens make affected canonical artifacts available independently of projection catch-up. Neo4j stores reified assertion nodes and evidence relationships. Qdrant, or another vector store you configure, holds immutable vectors and typed metadata, not canonical text. SQLite also stores vectors as packed floats. In the background, the broker embeds memories of the configured Ollama server that lack one. Semantic recall scans every stored vector, so it does not depend on Qdrant. A delayed or stale projection cannot authorize a fact: every candidate is hydrated and checked against SQLite.

Assertion validity and the revision at which PAL knew an assertion are separate half-open intervals. A correction closes a prior knowledge version, creates its surviving world-time intervals, and records the replacement. Unknown dates are not invented. Single-valued equal-authority disagreements become disputed. Multivalued corrections require a specific member. Exact supporting evidence and its trust class accompany every claim; assistant prose cannot establish an instrumented outcome.

Retrieval combines exact aliases, FTS5, vector candidates, and bounded relationship expansion, then rank fusion and optional graph ranking. Scope, temporal applicability, policy, erased state, evidence, and content revisions determine eligibility. Semantic and graph candidates are gathered within the retrieval deadline (`deadline_ms`, 500 ms by default); the scope lookup and the keyword retrieval wait for the memory worker, so a busy worker makes recall late, with `deadline_partial` coverage, instead of making it fail. The retrieval result includes coverage, snapshots, evidence IDs, and budgets for the inspector, CLI, and provenance records. Models receive a compact delimited packet instead (`packet.ts`): each recalled item's text once, with its kind, date, and citable evidence IDs. The token budget counts that packet, and long conversation passages, episodes and topics appear as an 800-character excerpt around the words they matched. A turn recalls automatically only when its message has a topic word and its route may receive memory, and it keeps at most eight items. Once the store holds 50 passages, lexical matches must clear a BM25 floor. A semantic match must score above 95% of the stored memories for that query, and never below 0.4. Automatic recall leaves out the message itself, earlier copies of it, the conversation's recent exchange, passages without a topic word, and passages that repeat one already selected. Because the model receives it without asking, automatic recall (`intent: "automatic"`) also never includes an unreviewed candidate, ranks a disputed record at half its relevance, and limits each kind of item: at most four passages (60% of the token budget), four notes (50%), two summaries (30%) and two disputed records (20%), while settled facts and statements are bounded only by the packet. Items a full kind leaves out are reported as omitted, so the model can search. An explicit search (`intent: "search"`, the default) lists every eligible record with its status. Each turn's recall record keeps per-kind counts and how many candidates it withheld; the broker health report gives the injection rate over the last seven days of recorded turns. A turn that may not write memory records nothing for its message, so earlier copies of it are left out by their text. Codex, Claude, and AntiGravity keep packets in their transcripts. An item it received in one of its last four completed turns that supplied memory is not sent again; Codex or Claude compaction, or a new provider thread, resets this. Policy changes and erasures invalidate in-flight packets and gate late output.

Erasure writes an fsynced external registry before suppression, traverses content lineage, scrubs canonical copies, and queues deletion across projection generations. The full-text index drops an erased row’s entries as it goes (FTS5 secure-delete), and a forget, an expiry that removed anything, and opening the store end with a truncating checkpoint, so neither the index nor earlier write-ahead log frames keep erased text. The conversation database zeroes the pages a scrub frees and truncates its log after the scrub commits; a database from before 2.0.3 is rewritten once when it is opened. Each erasure also scrubs the pre-migration backups PAL keeps, with the same statements and without changing their schema; an assertion version that erasure re-derives from independent surviving evidence is left whole there, so replaying the registry on a restored backup can re-derive it too. `Memory.erase` checks a preview’s revision and selection against the sources it has just read, before scrubbing, and the deletion that follows does not check them again, so a commit elsewhere in memory in between cannot leave scrubbed text recallable. An intent the canonical deletion did not finish is replayed at startup and when the memory worker restarts; one whose record or scope no longer exists is complete. Source-specific deletion can rederive an assertion from independent surviving witnesses. Explicit fact deletion includes its supporting occurrences. A receipt distinguishes immediate suppression from completed physical purge; unavailable dependencies keep purge pending. Restoration uses the current registry before rebuilding projections.

The collector runtime is transient and uses source epochs, sequence ordering, monotonic freshness, and explicit unknown states. Fish reports structured status and approved CWD metadata without command text. Hyprland observes window metadata with titles disabled by default; Kitty uses only configured read-only inspection endpoints and is told apart by window and process. Editors report open documents through an emitter, and the desktop's lock state can be observed; both are off like the others, and while the screen is locked nothing is observed. Repository metadata verifies checkout roots. Refer to [implementation status](implementation-report.md) for what is incomplete; the presence of schema tables does not mean every reference workflow is.

## Configurable memory review

SQLite owns statements, exact witness links, version history, effective retention, the curation queue and its decisions. Migrations 6 and 7 append these structures. Legacy pins had no uniqueness, so before migration 7 copies them into holds, a record with more than one active pin keeps its oldest, with every distinct note, and the others are released; migration 7's checksummed SQL is unchanged. Expiry, recall and forecasts take each record's retention decision from the shared planner (`retention.ts`); expiry's queries only narrow the scan to records past their own deadline that no active hold names. The scope key continues to use the saved chat host and project. Changing the review model changes the review configuration revision. Projection databases contain rebuildable copies. Retrieval hydrates each candidate through SQLite before it can enter a packet.

The service leases a candidate with its scope, source versions, effective evidence, temporal state, permitted neighbors, policy and erasure epochs. It computes a digest of those inputs. Inference runs outside the writer transaction. Each dispatch resolves the bound route, checks sensitivity and reserves budget. The writer verifies the lease, input digest and current authority again before writing an assessment or applying a decision. The digest covers everything the reviewer saw, so a change to those inputs rejects the result while an erasure elsewhere, such as routine expiry, does not; a synthesized summary is likewise published only over the evidence its model read. Reconfiguration makes old queued work stale. Automatic preservation binds the exact supporting excerpts to a bounded hold. Semantic acceptance additionally requires direct authority, no unresolved conflict and a separately validated adjudication. Decisions record the actor, rubric, before/after versions and route identity. Raw transcript expiry can scrub an assessment that used full context while leaving a content-free decision receipt available for undo.

To add a protocol adapter, implement `TaskProviderAdapter` from `broker/graph-memory/task-models.ts` and register it in `taskProviderAdapters()`. Provide processing classification, completion and output-mode capabilities, bounded generation, finish state, reported usage and identifiable model metadata where available. Invoke the attempt hook immediately before sending task content. Return the response as data. Validate the same local Zod schema for every transport. Use connection-scoped credential lookups through the existing resolver. A new saved-connection kind also needs a resolver entry and a declaration in the connection editor. Neither queue transitions nor canonical decision rules depend on the transport.

The ranking prior multiplies an already eligible, relevant score by at most 1.10. Optional reranking sees up to 32 eligible snippets before packet budgeting. It may order only supplied IDs. Rehydration after inference checks scope, policy, time, source versions and the erasure epoch. Explicit deep recall allows a longer foreground deadline. Summaries remain attributed derived artifacts with sentence-level evidence IDs and a source generation. The archived extractive summary remains available when synthesis fails.
