# Graph memory policy

Memory starts disabled. Existing PAL memory preferences govern normal chat capture and recall; collector permissions are separately opt-in in the graph inspector. Disabling capture preserves already-retained records. Explicit deletion uses the erasure workflow.

The default extraction model is `glm-5.3-flash:cloud`, and Settings can select another registered model. It is evaluated in [EV-01](evaluation.md#extraction-through-canonical-memory-ev-01). Enabling memory with cloud extraction allowed permits eligible source text to go through the configured loopback Ollama server to Ollama Cloud. This is independent of cloud chat recall, which defaults off. The source's local-only restriction is checked again before cloud extraction. Turn off cloud extraction to prevent these requests; no alternate extraction model is silently substituted. Embedding defaults to `nomic-embed-text` at the conversation's saved Ollama server. PAL refuses cloud-backed Ollama embedding models. Owners who select Gemini embeddings and separately enable cloud embedding consent allow eligible source passages and search queries to be sent to Google. Consent starts off and local-only passages are excluded. A knowledge collection that does not allow cloud models keeps its passages local-only, so a hosted embedding provider never receives them; allowing or withdrawing that consent applies to the passages already indexed, and withdrawing it stops an indexing run in progress. Changing the extraction or chat recall settings does not enable cloud embeddings.

Collector defaults disable Hyprland, Kitty, Fish, editor events, the lock state, filesystem events, titles, file content, and retained workspace history. Window titles require two controls: title capture must be on, and the window's application class must be listed in the title allowlist. The allowlist starts empty, and enabling title capture never extends it to every application. Approved roots are explicit paths; CWD/file metadata checks use resolved paths to reject symlink escapes. Kitty environment, command line, scrollback, and title content are discarded by its parser. Fish never emits its command line. Metadata observations do not grant desktop-control permissions. An editor emitter sends the path and kind of an event and never text; a path outside the approved roots is dropped when it arrives. While the session is locked nothing is observed, and after sleep every source is unknown until it is seen again. With the history toggle on, PAL keeps which files, folders and kinds of work were seen inside approved roots, with counts and durations, for the chosen number of days (7 by default, 90 at most): no title, command or text. Records merge while the same work goes on, leave with a folder that is no longer approved, and can be erased at any time. Without it, desktop observations remain transient. Assistants read their own project’s part, and hosted ones only when cloud recall is allowed.

Source witnesses are untrusted data. Strict DTOs reject unknown fields, unregistered predicates, invalid entity types, invalid temporal intervals, and fabricated quotations. Source trust distinguishes direct user statements, tool instrumentation, document claims, inference, and assistant summaries. A candidate proposal is not a verified fact, and repetition does not increase a stored confidence score. Restating a pending candidate (the same claim, modality, source authority and valid time, or for a statement the same wording) attaches the new source to that record as independent support instead of creating a duplicate. The record stays a candidate, keeps the lower confidence, and its candidate deadline restarts from the latest independent source. A restatement that the acceptance rule admits on its own promotes the record; the promoted version cites only witnesses that rule admits, so a question or hedge stays with the superseded candidate. Retention holds keep the evidence they already protect. Automatic recall never sends an unreviewed candidate to a model; an explicit memory search still finds it, labeled.

Default raw-turn retention is 30 days; candidate retention is 7 days. Expiration removes full conversation recall copies and non-supporting witnesses while retaining exact evidence used by accepted assertions when `retain_evidence` is enabled. Explicit forgetting also removes permitted evidence and affected managed chat passages. Erasure and expiration have distinct audit reasons. The current erasure registry must be preserved independently of older backups.

The supported trust boundary is one OS user. The broker's administrative memory methods are available to that user's authorized local client; arbitrary SQL/Cypher and internal projection commits are not model tools. Same-user programs can already access the private profile. Private directories and credential files must retain their configured modes.

Remaining restrictions and incomplete source lifecycle behavior are listed in [implementation status](implementation-report.md). This publication is not a claim that the complete reference design has passed all release gates.

## Curation and evidence retention

A project memory statement records an exact source passage, modality, source authority, category, recording revision and valid time. Each correction creates a successor. Captured assistant output stays assistant-attributed. An explicit user correction supplies a new user observation. Manual pins, automated grace and bounded preservation affect evidence retention. Factual acceptance requires a separate decision, exact citations and a current supported record. Neither retrieval frequency nor an extractor's original confidence increases authority.

The stored policy starts with a 48-hour at-risk window, 14 days of review grace, 30 days of preservation, and a 90-day cap on automatic unresolved extension. The default scope caps are 5,000 protected records and 50 MiB of unique supporting excerpts. Existing raw-passage and candidate durations survive upgrade. The same planner accounts for record deadlines, active holds and complete independent support bundles. Explicit forgetting follows the erasure registry even when a hold is active.

The default review budget is 100 requests, 100,000 estimated input tokens and 20,000 output tokens per UTC day. Requests have separate input and output caps. Unknown usage stays reserved. An optional monetary ceiling requires prices supplied by the user. Failures leave uncertainty intact and surface in the review inbox. The provider sees only the bounded task input. An unknown processing location blocks dispatch. An assessor may request review or propose preservation, while the canonical transaction alone changes storage or status.
